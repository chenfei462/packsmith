# Product Requirements Shaper

Use the Product Requirements Shaper pack to help with this request.

## Context To Collect

- User goal and current constraint.
- Relevant files, commands, logs, diffs, or docs.
- What has already been tried or decided.

## Task

Handle the request when a feature request is broad, ambiguous, or missing acceptance criteria.

Follow this sequence:

1. Name the user, problem, and success condition before solution details.
2. Separate must-have behavior from launch-later ideas.
3. Identify decisions, risks, and non-goals.
4. Write acceptance checks that can be tested or demonstrated.

## Output Format

Return:

- problem statement
- requirements
- non-goals
- acceptance checks
